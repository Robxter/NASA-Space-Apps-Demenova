## Open issues and risks
- Not expressible in plain SQL: per-field origin resolution inside OriginSpec maps for unbounded engine numbers
  (Pydantic still checks it); `provenance_ids` elements cannot be foreign keys (pattern checked only);
  `from_level → to_level` transitions not constrained (state machine lives in the engine, docs/spec/16).
- Contract nullability narrowed in the DB: `farms.owner_id` and `user_prefs.user_id` are null only for the demo /
  local-only cases, and local-only rows never reach Supabase.
- Farm ids are global primary keys: two devices choosing the same slug collide. The app should add a random suffix
  (frontend-engineer). A collision error also reveals that the id exists (low risk).
- Abuse: anonymous users can create unlimited farms and large polygons; enable CAPTCHA (README step 1); no row cap.
- Stale state is written by the engine; if the pipeline stops, the app must compare `newest_rain_data_at` with
  `stale_after_hours` from config/alerts.yaml (not hard-coded in SQL).
- Test fixtures insert into `auth.users`; if the hosted project refuses that, the tests need two real anonymous users.
